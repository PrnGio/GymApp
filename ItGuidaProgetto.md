# Progetto PDMIU

## Specifiche del progetto

Crea un'applicazione sviluppata in **Flutter** per almeno una piattaforma tra quelle supportate dal framework (Android, iOS, Web, Windows, macOS), seguendo le best practice e le linee guida specifiche della piattaforma. 

Non ci sono requisiti specifici in termini di funzionalità e ambito dell'applicazione: puoi decidere di sviluppare qualsiasi tipo di applicazione mobile che ritieni interessante o utile per dimostrare di aver acquisito le competenze di sviluppo Flutter richieste. Se hai dubbi o non sei sicuro che un'idea di progetto sia accettabile o meno, sentiti libero di inviarmi una breve descrizione del tuo progetto. 

* **Progetto individuale:** Il progetto è inteso come lavoro individuale.
* **Progetto di gruppo:** Nel caso di progetti particolarmente complessi, è possibile proporre un lavoro di gruppo (massimo 3 persone). Prima di iniziare a lavorare al progetto, inviami una proposta e una descrizione di come intendi suddividere le responsabilità tra i partecipanti.

---

## Consegna del progetto

Il progetto deve essere consegnato **almeno 48 ore prima dell'esame** *(es. se l'esame è alle 14:00 del 16 gennaio, si prega di consegnare il progetto entro le 14:00 del 15 gennaio)*. 

Consegna il progetto inviando un'e-mail con le seguenti informazioni:
1. La sessione d'esame a cui parteciperai (data);
2. Il tuo nome completo e numero di matricola;
3. Una brevissima descrizione del progetto (massimo 1 o 2 righe);
4. L'URL del repository GitHub pubblico che contiene il progetto.

> **Nota:** Se preferisci non utilizzare GitHub, puoi consegnare il progetto come archivio ZIP tramite e-mail.

### Requisiti del Repository e `README.md`

Il repository GitHub deve contenere l'intero progetto e tutti i file accessori necessari per compilare ed eseguire l'applicazione. Devi aggiungere un file `README.md` nella directory principale, contenente una breve descrizione del progetto. In particolare:

* **A. Dati autore:** Nome e numero di matricola.
* **B. Titolo:** Titolo del progetto.
* **C. Panoramica:** Breve panoramica dell'idea del progetto e delle funzionalità principali dell'applicazione.
* **D. Esperienza utente (UX):** Descrivi come vengono eseguite le azioni utente più comuni tramite l'interfaccia utente (UI) dell'applicazione. Aggiungi almeno un paio di screenshot.
* **E. Tecnologia:** 
  * Se sono stati utilizzati pacchetti Dart/Flutter specifici, descrivi quali e perché.
  * Se hai fatto scelte implementative degne di nota, descrivile.
  * Se la tua applicazione memorizza dati o comunica con un server remoto, descrivi perché e come.
  * Se hai riscontrato problemi durante l'implementazione e sei riuscito a risolverli, descrivi cos'è successo.

Il file `README.md` non deve essere molto lungo, ma dovrebbe evidenziare sinteticamente i punti principali della tua app e le scelte implementative che hai effettuato.

## Esame orale

L'esame orale consiste in una presentazione/demo del progetto:
* Fornirai una panoramica dell'applicazione e delle sue funzionalità principali.
* Mostrerai i casi d'uso più comuni e descriverai le tue scelte implementative.
* Esamineremo poi parti specifiche del codice dell'applicazione e discuteremo le scelte fatte e le possibili aree di miglioramento.

## Criteri di valutazione

Il progetto verrà valutato con la somma dei seguenti criteri:

| Criteri | Contributo al voto |
| :--- | :---: |
| Applicazione mobile Flutter funzionante e priva di crash per una piattaforma. Punti bonus in base al numero di funzionalità. | **18–20** |
| Navigazione tra più schermate/pagine utilizzando elementi UI specifici della piattaforma (drawer, bottom bar, ecc.). Punti bonus in base alla complessità. | **+1–2** |
| Persistenza dei dati sul dispositivo (impostazioni, file, database, ecc.). | **+2** |
| Comunicazione con un servizio remoto (HTTP o altro). | **+2** |
| Design dell'interfaccia utente responsive, che supporti almeno due modalità (orizzontale/verticale, piccolo/grande, ecc.). | **+2** |
| Utilizzo di un pacchetto per lo state-management. | **+1** |
| Attenzione ai dettagli nella UX, elementi UI personalizzati, cura per la tipografia, schema di colori personalizzato, ecc. | **+1** |
| Multipiattaforma (l'app funziona su 1 o più altre piattaforme). | **+1** |
